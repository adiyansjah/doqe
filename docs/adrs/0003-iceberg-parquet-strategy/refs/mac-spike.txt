Method
------
This is a hand-compiled summary of retained logs, build trees, probe outputs
and source artifacts. The replay script checks both compiler drivers and the
static runtime archives against the macOS doqe pin, verifies the candidate
source archive hashes, and builds in a fresh mktemp directory under /tmp.
CMake and Ninja were already installed.
Native libraries were built from source. Python 3.12.11, PyIceberg 0.12.0,
and PyArrow 26.0.1 were used in an isolated fixture-generator environment.
No system installation, doqe build, or dev01 access.

Elapsed seconds are wall time from /usr/bin/time -p. Configure time includes
dependency fetches done by CMake. Build time includes build-time fetches and
linking where applicable. Top-level source downloads and Python setup are outside
the timings. The initial attempts overlapped and contain warm retries. The
standalone script builds each reader in a fresh build tree in sequence. These
are build observations with different dependency and codec closures, Release
flags and network conditions. Carquet's probe reads three Parquet profiles,
Arrow's probe reads the uncompressed baseline, and iceberg-cpp plans and reads
one complete Iceberg snapshot over that baseline. The build times and sizes
describe those configurations. Scan throughput was outside the spike.

Archive counts and sums use the paths listed as static inputs of the probe
link command, excluding LLVM runtime archives. They count archive bytes before
linking, which includes code the linker may not select. Executables are unstripped
Mach-O file bytes. Dependency counts are distinct external source projects
acquired by the candidate build, including header-only projects, excluding the
candidate itself, in-tree vendored code, system/SDK libraries, C++ runtime,
build tools and Python fixture dependencies. Arrow and Parquet share one source
project. Static archive count and source project count measure different things.

Fixture and value checks
------------------------
One PyIceberg SQLite-backed generation produced a local, unpartitioned,
format-v2 table with one snapshot, one manifest list, one data manifest
and one Parquet data file (no delete files). Both Avro containers used
the null codec. The generator verified the table through PyIceberg and
reported absolute file URIs. Parquet fields carry IDs 1 and 2, and both
columns are nullable. The generated metadata includes the name mapping
added by PyIceberg's add_files. F03.6 adds an independent field-ID fixture
whose active metadata omits this property. Each native probe output was compared by diff to
the following independently specified rows, with an empty string in row 2
and a null string in row 3.

  (42, "hello")
  (null, "")
  (-3, null)
  (0, "é")

Carquet read one row group for each of three files. The profiles were
uncompressed/PLAIN/V1, Snappy/dictionary/V1, and zstd/dictionary/V2.
PyArrow reported RLE and PLAIN for the baseline, and RLE_DICTIONARY,
RLE and PLAIN for the dictionary samples. Carquet's probe used ordinal
access on this controlled fixture. The public schema API does not expose
Parquet field IDs at this pin even though its internal wire schema retains
them. The probe uses the library's path API. A doqe buffer adapter,
per-reader allocations, and rename/reorder behavior were not verified.

Arrow read values and null definition levels with the low-level typed API
on the uncompressed baseline and asserted both Parquet field IDs.
iceberg-cpp planned one scan task from the metadata JSON and both Avro
layers, opened that task, and read the same rows from its Arrow C stream.

Initial attempts and recoveries
-------------------------------
Carquet: The first configure took 17.61 s and failed to generate our
C++ consumer target because Carquet declares only the C language.
Enabling CXX for the throwaway probe fixed that (warm configure 1.08 s,
build/link 6.29 s). No Carquet reader source patch was applied.
Arrow: 49.68 s configure, 71.83 s archive build, 1.45 s probe reconfigure,
0.79 s incremental probe build/link. Thrift was fetched from Apache's
archive by overriding the upstream download URL at the same pin.
iceberg-cpp: 73.34 s configure, 119.85 s archive build, 1.41 s probe
reconfigure. Corrected two probe API call signatures after a 0.66 s
compile failure. The next link attempt (1.25 s) failed because the
Boost.UUID link interface added -latomic, absent from the Mac SDK.
BOOST_UUID_LINK_LIBATOMIC=OFF fixed it (1.29 s reconfigure, 0.15 s
incremental link). No iceberg-cpp source patch was applied.
The first packaged replay exposed path quoting in Arrow's nested zlib
CMake configure. Passing the tested unquoted flag value resolved it.
