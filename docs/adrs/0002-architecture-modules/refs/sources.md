# ADR-0002 sources

## Comparable C++ projects

- **DuckDB · read 2026-11-21.** The build divides parsing, planning, optimization, execution, catalog, and storage into source subdirectories and combines object files in the static engine archive. This is a precedent for responsibility-based directories within a broader library. [DuckDB src build](https://raw.githubusercontent.com/duckdb/duckdb/main/src/CMakeLists.txt)
- **Velox · read 2026-11-21.** The build has separate type, vector, expression, and execution directories. [Velox build](https://raw.githubusercontent.com/facebookincubator/velox/main/velox/CMakeLists.txt)
- **ClickHouse · read 2026-11-21.** The build has separate Columns, DataTypes, Planner, QueryPipeline, Formats, and Server directories and groups common and I/O sources into a single library. Source directory boundaries and library boundaries can differ. [ClickHouse src build](https://raw.githubusercontent.com/ClickHouse/ClickHouse/master/src/CMakeLists.txt)
- **StarRocks BE · read 2026-11-21.** Explicit target links for the join core name expression, runtime, chunk, column, and type libraries. The storage base also links the shared chunk, column, and type targets, giving execution and storage common data contracts. [StarRocks BE execution build](https://raw.githubusercontent.com/StarRocks/starrocks/main/be/src/exec/CMakeLists.txt), [StarRocks BE storage build](https://raw.githubusercontent.com/StarRocks/starrocks/main/be/src/storage/CMakeLists.txt)
- **Apache Doris BE · read 2026-11-21.** The execution and storage build files declare distinct static targets, `Exec` and `Storage`. The execution build also places its simulator in a separate executable. [Doris BE execution build](https://raw.githubusercontent.com/apache/doris/master/be/src/exec/CMakeLists.txt), [Doris BE storage build](https://raw.githubusercontent.com/apache/doris/master/be/src/storage/CMakeLists.txt)
- **Apache Arrow C++ · read 2026-11-21.** The C++ build organizes arrays, compute, and I/O in separate source directories and defines the library `arrow_testing` in the CMake package `ArrowTesting` when `ARROW_TESTING` is enabled. [Arrow C++ build](https://raw.githubusercontent.com/apache/arrow/main/cpp/src/arrow/CMakeLists.txt)
## Iceberg

- **Apache iceberg-cpp · read 2026-11-21.** The core build includes manifest, inclusive and strict metrics, and residual evaluators alongside scan planning. This supports putting Iceberg predicate and pruning rules in table. Library selection is a separate decision. [iceberg-cpp core build](https://raw.githubusercontent.com/apache/iceberg-cpp/main/src/iceberg/CMakeLists.txt)
- **Apache Iceberg specification · read 2026-11-21.** The spec defines field IDs, file and delete applicability by partition and sequence number, equality-delete null matching, and Iceberg v3 types including `timestamp_ns`, `variant`, and `geometry`. [Table spec](https://iceberg.apache.org/spec/)
- **Apache Iceberg REST API · read 2026-11-21.** The commit endpoint distinguishes a conflict from server and gateway responses that leave publication state unknown. [REST catalog OpenAPI](https://raw.githubusercontent.com/apache/iceberg/main/open-api/rest-catalog-open-api.yaml)

## Column layout and build rules

- **Apache Arrow columnar specification · read 2026-11-21.** Physical array layouts specify value buffers, separate validity bitmaps, and offsets for applicable variable-size and nested arrays. [Columnar format](https://arrow.apache.org/docs/format/Columnar.html)
- **Apache Arrow C Data Interface · read 2026-11-21.** The specification defines an in-process, zero-copy interchange interface that can be used without linking an Arrow library. A producer supplies a release callback to manage the lifetime of the exported buffers. [C Data Interface](https://arrow.apache.org/docs/format/CDataInterface.html)
- **Apache Arrow C Stream Interface · read 2026-11-21.** The stream ABI uses callbacks to return successive arrays with a common schema and has a separate stream release callback. [C Stream Interface](https://arrow.apache.org/docs/format/CStreamInterface.html)
- **Apache Arrow ABI header · read 2026-11-21.** The official Apache-2.0 header contains the C Data and C Stream declarations. The C Data specification describes copying the declarations for standalone use. [C Data specification](https://arrow.apache.org/docs/format/CDataInterface.html), [official arrow/c/abi.h](https://github.com/apache/arrow/blob/main/cpp/src/arrow/c/abi.h)
- **CMake 3.25 · read 2026-11-21.** Target links propagate usage requirements, and CMake permits some cycles among static libraries. The project therefore needs explicit graph and include checks to enforce its stricter rules. [target_link_libraries](https://cmake.org/cmake/help/v3.25/command/target_link_libraries.html)
