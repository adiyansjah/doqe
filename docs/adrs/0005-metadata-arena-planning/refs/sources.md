# ADR-0005 sources

## Iceberg

- Read 2026-11-21. Checked the v2 top-level required keys, `refs.main` agreement, the v1/v2 Java `-1` sentinel, snapshot schema IDs and manifest-list locations, and the JSON partition fields `transform` and `source-id`. M03 validates the keys used for planning. [Table metadata](https://iceberg.apache.org/spec/#table-metadata-fields) · [Snapshots](https://iceberg.apache.org/spec/#snapshots) · [Snapshot ID assignment](https://iceberg.apache.org/spec/#assignment-of-snapshot-ids-and-current-snapshot-id) · [JSON serialization](https://iceberg.apache.org/spec/#appendix-c-json-serialization)
- Read 2026-11-21. Verified manifest-list IDs and types for v2: 500 string, 501 and 503 long, 502 int, 515 long and 517 int. The full v2 spec also requires list fields 504–506, 512–514 and 516, which M03 skips. [Manifest lists](https://iceberg.apache.org/spec/#manifest-lists)
- Read 2026-11-21. Java and PyIceberg v2 list writers emit the Avro `format-version` header. The Iceberg spec defines the list schema and v1 defaults without requiring a list version header. M03 uses absence of ID 515 or 517 as the legacy signal for unversioned lists. [Manifest lists](https://iceberg.apache.org/spec/#manifest-lists) · [Version 2](https://iceberg.apache.org/spec/#version-2) · [Java writer](https://github.com/apache/iceberg/blob/main/core/src/main/java/org/apache/iceberg/ManifestListWriter.java) · [PyIceberg writer](https://github.com/apache/iceberg-python/blob/main/pyiceberg/manifest.py)
- Read 2026-11-21. Verified required entry IDs 0 int and 2 struct, and optional entry IDs 1, 3 and 4 long. Verified required v2 data-file IDs 100 and 101 string, 102 struct, 103 and 104 long, and 134 int. Iceberg represents structs as Avro records and records each struct field's integer ID in the Avro field annotation. Optional values are null unions. The header specifies the manifest format version, partition spec ID and content. [Manifest schema](https://iceberg.apache.org/spec/#manifest-schema) · [Manifest headers](https://iceberg.apache.org/spec/#manifests) · [Iceberg Avro mapping](https://iceberg.apache.org/spec/#avro)
- Read 2026-11-21. Null snapshot IDs inherit from the manifest's list entry. For v2, null ADDED sequence values inherit the manifest sequence. Both sequences for EXISTING and DELETED must carry their original values. The v1 header can omit `format-version`, and upgraded tables may retain v1 metadata. The spec prescribes v1 defaults and backward compatibility. M03 rejects legacy manifests. [Manifest schema](https://iceberg.apache.org/spec/#manifest-schema) · [Inheritance](https://iceberg.apache.org/spec/#inheritance) · [Sequence inheritance](https://iceberg.apache.org/spec/#sequence-number-inheritance) · [Version 2](https://iceberg.apache.org/spec/#version-2)
- Read 2026-11-21. Verified the maximum non-reserved table field ID of 2147483447. Iceberg uses field IDs for projection and calls for the identity partition value when a source field is absent from a data file. M03 returns `Unsupported` for that case because it skips partition values. Iceberg lists lowercase `parquet` among file formats. The planner accepts case variants and emits canonical `PARQUET`. [Reserved field IDs](https://iceberg.apache.org/spec/#reserved-field-ids) · [Column projection](https://iceberg.apache.org/spec/#column-projection) · [Manifest schema](https://iceberg.apache.org/spec/#manifest-schema)

## Avro, JSON and local paths

- Read 2026-11-21. Verified the eight primitive writer types and rules for records, enums, arrays, string-keyed maps, unions, fixed and named types. Fullnames and enclosing namespaces resolve references to record, enum and fixed definitions. Names must be defined before use, and recursive records are valid Avro. Unions use writer-order branch indexes, so either order of the null and long branches can be read. M03 rejects recursion. [Avro 1.12.0 primitive types](https://avro.apache.org/docs/1.12.0/specification/#primitive-types) · [Complex types](https://avro.apache.org/docs/1.12.0/specification/#complex-types) · [Names](https://avro.apache.org/docs/1.12.0/specification/#names) · [Binary encoding](https://avro.apache.org/docs/1.12.0/specification/#binary-encoding)
- Read 2026-11-21. The writer schema determines record field order. Binary encoding defines zigzag integers, UTF-8 strings, and array/map blocks with negative counts followed by block byte size. Additional schema attributes can carry metadata without changing the encoding. [Avro 1.12.0 binary encoding](https://avro.apache.org/docs/1.12.0/specification/#binary-encoding) · [Schema declaration](https://avro.apache.org/docs/1.12.0/specification/#schema-declaration)
- Read 2026-11-21. Verified the Avro header, writer schema, sync marker and data block count, size and payload framing. A zero-count, zero-size block still carries its sync marker. Absent codec means null. Avro requires null and deflate for general-purpose support and describes one or more data blocks. M03 supports null only and accepts a header-only container as an extension. [Avro 1.12.0 object container files](https://avro.apache.org/docs/1.12.0/specification/#object-container-files)
- Read 2026-11-21. JSON defines number grammar and UTF-8 interchange, recommends unique object member names and permits implementation limits. Duplicate-key rejection, exact int64 conversion and parser ceilings are doqe choices. [RFC 8259, sections 4, 6, 8 and 9](https://www.rfc-editor.org/rfc/rfc8259.html)
- Read 2026-11-21. URI schemes are case-insensitive. The file URI grammar allows an absolute path with or without an authority delimiter. RFC 8089 treats `localhost` as local. M03 limits file URIs to empty authorities and rejects percent escapes. Bare absolute paths are a doqe input convention. [RFC 3986, section 3.1](https://www.rfc-editor.org/rfc/rfc3986.html#section-3.1) · [RFC 8089, section 2](https://www.rfc-editor.org/rfc/rfc8089.html#section-2)
